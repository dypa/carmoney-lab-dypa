# intent_MILEAGE — пробег авто в расчёте решения

## 1. Замысел

Добавить в расчёт решения по заявке проверку пробега автомобиля: если пробег
не больше 400 000 км — решение считается как сейчас; если больше — решение
`review` (источник: формулировка задачи из интервью).

## 2. Зачем

Сегодня решение approve / review / reject рождается только из LTV
(код: backend/src/Domain/DecisionEngine.php), а пробег участвует лишь в
валидации ввода 0…500 000 км (код:
backend/src/Domain/ApplicationValidator.php) и не влияет на решение.
Правило закрывает этот пробел: высокие пробеги не проходят одобрение
автоматически, а уходят на ручную проверку.

## 3. Constraints

- Порог пробега — 400 000 км, «не больше» = при превышении решение `review`
  (источник: формулировка задачи из интервью).
- Пробег ровно 400 000: является ли «не больше» границей ≤ или <, — не
  отвечено; см. Open questions (источник: интервью, вопрос 2 — «уточнить у
  риск-менеджмента»).
- Валидационный предел пробега 500 000 км не меняется: значения 400 001…500
  000 должны проходить валидацию, иначе правило недостижимо (код:
  backend/config/rules.php; код: backend/src/Domain/ApplicationValidator.php).
- Отсутствующий пробег в заявке → ошибка валидации 422, решение не
  вычисляется; пути «пробег неизвестен» нет и не вводим (ответ в интервью,
  вопрос 3; код: backend/src/Domain/ApplicationValidator.php — отсутствие
  поля нормализуется в -1 и отклоняется; код: db/schema.sql — колонка
  NOT NULL; поле формы required).
- Если LTV уже дал `review`, хороший пробег не переводит его в `approve`:
  правило только ужесточает, не смягчает (ответ в интервью, вопрос 4).
- Если LTV дал `reject`, а пробег > 400 000 — какое решение возвращать, не
  отвечено; см. Open questions (источник: интервью, вопрос 1 — «не знаю»).
- Решение reject по LTV не смягчается пробегом до review — допущение,
  зафиксированное в плане, но не подтверждённое риск-менеджментом; см. Open
  questions (код: docs/plan/plan_MILEAGE.md).
- Все пороги и лимиты — из конфига, а не из кода (код: docs/agent-rules.md /
  AGENTS.md — бизнес-числа не хардкодим).

## 5. Не входит

- Правка валидации пробега: предел 500 000 км, тексты ошибок 422, поле
  формы (источник: базовый список «Не входит» из плана, подтверждён
  вопросом 5 интервью как минимальный).
- Путь «пробег неизвестен»: нормализация, БД, форма (ответ в интервью,
  вопрос 3 — 422 как сейчас).
- Расчёт лимита по возрасту авто — отдельная задача LOAN-12 (код:
  backend/config/rules.php — справочник возрастных лимитов заполнен, но не
  подключён к расчёту).
- Причина review/reject в ответе API — открыт, см. Open questions; контракт
  ответа без решения риск-менеджмента не меняем.
- Feature/HTTP-тесты и e2e-сценарии — отдельная часть работы.
