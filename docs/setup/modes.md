# Режимы Kilo Code: code vs ask

Источник — `docs/setup/tools.md` (раздел «Агенты и режимы», задание 1.2.1). Прямых
определений в `AGENTS.md` и `kilo.jsonc` нет — там описаны только права (`permission`)
и конвенции.

Переключатель режима — в панели Kilo или шорткатом `Cmd+.` / `Ctrl+.`.

## code

- **Что делает:** правит файлы и запускает команды (формулировка `tools.md:124`).
- **Доступные действия:** чтение, запись и редактирование файлов (`read`, `edit`,
  `write`), запуск shell-команд (`bash`) в рамках `permission` из `kilo.jsonc`.
- **Когда выбирать:** реализация, правки кода, прогон тестов и линтера, работа с git.
- **Ограничения:** всё, что в `permission` помечено `deny`, агент не выполнит даже в
  этом режиме; `ask` — выполнит только с подтверждения человека (см.
  [`agent-rules.md`](../agent-rules.md)).

## ask

- **Что делает:** только читает и отвечает (формулировка `tools.md:124`).
- **Доступные действия:** `read`, `grep`, `glob` — без `write`, `edit` и без
  мутирующих `bash`-команд. Запросы на изменение файлов или запуск команд в этом
  режиме не выполняются; агент формулирует ответ или предлагает план.
- **Когда выбирать:** разбор кода, ревью, ответы на вопросы, обсуждение спеки или
  архитектуры, разведка по репозиторию (`@scout`-подобные задачи).
- **Следствие:** в `ask` нельзя реализовать задачу — для правок нужно переключиться
  на `code`.

## Сводка

| Режим | Файлы | Команды bash | Назначение |
|---|---|---|---|
| `code` | read / write / edit | read-only и мутирующие, по `permission` | реализация правок |
| `ask` | read-only | не выполняет | чтение, ответы, план |
| `plan` | read-only | не выполняет | построение плана перед записью |
| `debug` | read / write / edit | как у `code` | отладка (упомянут в `tools.md`) |

`plan` и `debug` упомянуты в `tools.md:124` кратко; подробное описание — в карточках
дня 1 (1.2.1).
